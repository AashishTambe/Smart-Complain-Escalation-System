├─ id (Primary Key)
├─ setting_name (Unique name)
├─ max_escalation_level (1-5)

├─ medium_priority_sla_hours (Configurable)
├─ high_priority_sla_hours (Configurable)
├─ auto_escalation_enabled (Boolean)
├─ notify_on_escalation (Boolean)
├─ escalation_levels (Description text)
├─ created_at (Timestamp)
└─ updated_at (Timestamp)

🔄 HOW IT WORKS
═════════════════════════════════════════════════════════════════════════════════════════════════════

BEFORE (Old Way - Hardcoded):
Escalation values hardcoded in Java → Can only change with code update

AFTER (New Way - Dynamic):
Settings in database → Admin changes via panel → System reads and applies instantly


⚡ EXAMPLE FLOW
═════════════════════════════════════════════════════════════════════════════════════════════════════

1. Admin logs in as ADMIN user
2. Opens Escalation Settings panel
3. Creates new configuration "VIP Support"
   - Max Level: 2
   - HIGH SLA: 1 hour
4. A HIGH priority complaint comes in
5. After 1 hour, escalation job runs
6. Job reads active settings
7. Sees HIGH priority has 1-hour SLA
8. Escalates complaint to Level 2
9. Notification sent to manager
10. System logs the escalation
